# 高中生活模拟器 · 蓝图集索引

本文件是**主蓝图**：它不写系统设计（那在 `总设计案.md`），只回答"按什么顺序做、每步交付什么、凭什么算完成"。

当前只声明 `BP-ROOT`。领域蓝图（BP-01…BP-05）在你确认设计后按阶段提取，不预建空壳——避免出现五个只有标题的文档，读起来像进度，其实是占位。

## 总体阶段与依赖

```
P0 骨架与数据契约
 └─ P1 模拟内核（时间/精力/行动）
      ├─ P2 学科图谱与考试（含赋分）
      └─ P3 五育评价与档案
           └─ P4 剧情与 AI 叙事
                └─ P5 前端闭环（可玩）
                     └─ P6 平衡校准与内容填充
```

P2 与 P3 可以并行（都只依赖 P1 的状态树，互不读对方）；P4 依赖 P3 的 evidence 结构；P5 必须等 P1–P4 的接口稳定后才动，否则界面会跟着内核返工三遍。

## 各阶段的执行合同

### P0 · 骨架与数据契约（约 0.5 天）

- **输入**：本文件 + 总设计案的数据模型节。
- **产出**：可 `npm run dev` 的空壳；`src/content/schema.ts`（Zod）；`scripts/validate-content.mjs`；三条架构测试（分层、无循环依赖、数据合法）。
- **不做**：任何界面设计、任何玩法逻辑。
- **失败信号**：schema 写得太松（什么都通过）或太紧（改数据要改代码）。判据是"加一个新学科只需加 JSON，不改 TS"。

### P1 · 模拟内核（约 2 天）

- **输入**：P0 的 schema。
- **产出**：`tickWeek(state, plan) → { state', report }` 纯函数；`applyCommand(state, cmd)`；16 决策点的排程结构（5 全天重点 + 5 晚间 + 6 周末）；全天重点的乘数结算；8 套模板数据；RNG 派生规则；`content/balance.json` 全部参数外置。
- **退出条件**：除上文哈希一致性外，还要有一条"同一周换顺序执行同样行动，结果一致"的测试——这条能挡住大部分隐式状态 bug。
- **失败信号**：结算函数开始 `if` 判断"这是第几周"。周次应该是数据，不是分支。

### P2 · 学科图谱与考试（约 2 天）

- **输入**：P1 的状态树。
- **产出**：图谱加载与校验（对称边、权重 0–1、无自环）；三条通道的纯函数；命题器；IRT 得分器；赋分器；错题本聚合。
- **退出条件**：赋分官方算例（85 → 88）逐位一致；把某单元 mastery 从 0 拉到 60，其关联单元的单次收益必须单调上升；confusion 跨过 60 时错误率必须跳变。
- **失败信号**：为了让某条测试通过而写特判。参数该调的是 `balance.json`。

### P3 · 五育评价（约 1 天）

- **输入**：P1 的行动与 P2 的考试结果。
- **产出**：Evidence 生成器（行动/事件 → 证据）、五维加权、时间衰减、档案 HTML/Markdown 片段。
- **退出条件**：同一存档重复生成档案，字节级一致；删掉一条 documented 证据后分数下降符合公式；五维分数极值不越界。
- **失败信号**：档案文案开始硬编码"你很努力"这类与数据无关的句子。文案必须由数据驱动。

### P4 · 剧情与 AI（约 1.5 天）

- **输入**：P3 的 evidence 与 P1 的关系值。
- **产出**：事件 DSL 与校验器；调度器；14 个事件；4 个 NPC 卡；FactSheet 生成器；叙事三道闸（数字/专名/断言）；语气梯度表；Template/Mock/OpenAICompat 三个 provider；本地代理 server/index.mjs（/api/chat、/api/models、/api/health）。
- **退出条件**：模板模式下 18 周无死路；任意 provider 抛错、超时、返回坏 JSON 时，游戏继续；100 段抽检中数字/专名/事件零虚构；同一 scene + 同一 digest 命中缓存。
- **失败信号**：AI 的返回被写进 `GameState` 的数值字段。只允许写 `narrative` 这类纯展示字段。

### P5 · 前端闭环（约 3 天）

- **输入**：P1–P4 的稳定接口。
- **产出**：16 决策点周计划板（模板切换 / 复制上周 / 拖拽与点选）、日结算快讯、知识星图、选科面板、成绩单与错题本、五育雷达与综评档案、事件对话（含「依据」折叠面板）、设置、存档。
- **退出条件**：18 周主路径走通；竖屏；刷新不丢；首屏预算；键盘可达；周计划板能在 60 秒内排完一周。
- **失败信号**：界面里出现"计算"逻辑。所有数字必须来自 `sim` 的 selector。

### P6 · 平衡与内容（约 1 天，可能反复）

- **输入**：全部。
- **产出**：参数表、目标分布、内容补全、体验打磨。
- **退出条件**：三档玩家分布命中总设计案的目标区间；你的试玩反馈闭环一次。
- **失败信号**：靠改文案掩盖数值问题。

## 跨域接口（先定，后写）

| 接口 | 形状 | 谁依赖 |
|---|---|---|
| `SimKernel` | `newGame(seed, profile) / tickWeek / applyCommand / selectors` | UI、AI |
| `ContentPack` | 学科、单元、边、行动、事件、NPC、平衡参数（全部 JSON + Zod） | 全系统 |
| `NarrativeProvider` | `renderScene / renderDialogue / renderEvaluation` | 剧情、档案 |
| `NarrativeFacts` | `buildSheet(state, week) → FactSheet` / `verify(text, sheet) → Violation[]` | 剧情、档案、UI |
| `SaveStore` | `save(slot, blob) / load(slot) / migrate(blob)` | UI |
| `EventBus` | 结算产出的只读事件流，供 UI 播动画与 AI 取上下文 | UI、AI |

规则：UI 只能通过 `selectors` 读状态，不能直接改；AI 只能读 `EventBus` 与状态摘要，不能写状态。

## 活动阶段合同

任意活动步骤只允许由真实问题触发的一层临时问题支线；关闭后必须回到父步骤。

触发条件（三者之一，且必须留下证据）：

1. 出现可观察的错误（测试红、报错、界面坏）；
2. 退出条件未满足（例如性能 80ms > 预算 50ms）；
3. 实际阻塞（依赖缺失、数据错误）。

支线规则：绑定父步骤、记录触发证据、不扩大产品范围、不新增完成分母、最多一层、同时只开一条。解决后关闭并回到父步骤的原顺序。

## 停止条件

出现以下任一情况，停下并回到你这里，不自行扩大范围：

- 首版范围需要新增一个**系统级**模块（不是参数、不是文案）；
- 内容量估算超出首版 1.5 倍；
- 平衡测试连续 3 轮仍打不进目标区间；
- 任何需要账号、付费、部署到公网的动作；
- 你明确说"停"。
